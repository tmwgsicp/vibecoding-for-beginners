## 部署是什么？为什么要学？

你在本地电脑写好了代码，能跑了。

但是**只有你自己能用**。

**部署就是：把代码放到服务器上，让别人通过网址访问。**

### 小白最大的困惑

小白最大的问题不是技术，而是**根本不知道这些概念是什么**：

- localhost 是什么？
- 域名和 IP 有什么关系？
- HTTP 和 HTTPS 有什么区别？
- 怎么让代码从"只能本地跑"变成"别人能访问"？

**这些背景知识的缺失，是部署最大的障碍。**

## 背景知识科普

### localhost、IP、域名的关系

**类比：你家的地址**

- **localhost** = "我家"（只有你自己知道）
- **IP 地址** = "北京市朝阳区XX路XX号"（精确地址，但难记）
- **域名** = "王府井"（好记的名字，指向同一个地方）

**对应到网站：**

- **localhost（127.0.0.1）** = 你的电脑
  - 只有你能访问
  - 别人访问不了
  
- **服务器 IP** = 47.93.123.45（示例）
  - 任何人都能访问
  - 但很难记
  
- **域名** = example.com
  - 好记
  - 指向服务器 IP

**怎么让别人访问？**

```
你的电脑（localhost） → 代码上传 → 服务器（IP）
                                    ↓
                            买域名，指向这个 IP
                                    ↓
                        别人访问 example.com，就能看到你的网站
```

---

### HTTP 和 HTTPS 的区别

**HTTP** = 不安全的传输
- 数据明文传输
- 容易被窃听
- 浏览器会警告"不安全"

**HTTPS** = 安全的传输
- 数据加密
- 需要 SSL 证书
- 浏览器显示"安全"

**为什么要用 HTTPS？**
- 浏览器不会警告
- 某些功能必须 HTTPS（比如调用摄像头、地理位置）
- 看起来更专业

**怎么获得 HTTPS？**

后面会讲，用 Cloudflare 可以免费获得。

## 我的部署方案

### 为什么不用传统方式？

传统部署要在服务器上敲很多命令，配置很复杂，出错了很难调试。

**对小白来说，太难了。**

### 早期: 1Panel

一开始我用的是 1Panel，一个可视化的 Linux 服务器管理面板：有界面，不用敲终端命令，一台服务器可以部署多个网站。

用了一段时间，有两个问题：

1. **还是要我自己去手工操作，非常不便捷**
2. **感觉它跑起来比较重**

### 现在: vibe-launch

所以我自己开发了 **[vibe-launch](https://github.com/tmwgsicp/vibe-launch)**：agent 原生的轻量部署工具，开源免费。

- **不用手工操作:** 在 Claude Code、Codex 这类 AI 编程工具里说一句"部署 myapp"，它就帮你部署
- **轻量:** 用你本地的 SSH 直连服务器，服务器上不用常驻一套面板
- **自动识别项目怎么跑:** 它会看你的项目是什么类型(Vue/Next/Python/Node/静态页…)，给出部署命令、端口和健康检查
- **域名和 HTTPS 一起搞定:** 登记"域名 → 项目"就能生效。新服务器它自动装 Caddy；已经装了 1Panel 的服务器直接用 1Panel 的，不打架
- **所有服务器和项目记在一份本地清单里:** 哪个项目在哪台、怎么部署的，不用靠脑子记

### 先懂一点 Docker

**你可能会在部署时看到"Docker"、"容器"这些词。**

**Docker 是什么？**

简单理解：**Docker 就是把项目和环境打包在一起的工具。**

类比快递：
- 你做了蛋糕（你的项目）
- 用保温箱装好（Docker 容器）
- 保温箱里有温度控制（运行环境）
- 快递到任何地方，打开就能吃（部署到服务器，启动就能跑）

**你需要学 Docker 吗？**

**不需要。** 就像用微信不需要懂网络协议。

**但要知道一点：**

如果遇到问题问 AI，提到"我的项目是用 Docker 跑的"，AI 能给更准确的建议。

## 为什么选海外服务器？

### 国内服务器的麻烦

**需要域名备案：**
- 提交各种资料
- 等几周审核
- 非常麻烦


### 海外服务器

**优点：**
- 不需要备案
- 买了就能用
- 便宜

**缺点：**
- 访问速度稍慢（但用 Cloudflare CDN 可以缓解）

**推荐：**

**国外厂商：**
- Vultr
- DigitalOcean
- Linode

**国内大厂的海外节点：**
- 阿里云海外服务器（新加坡、香港等）
- 腾讯云海外服务器
- 优点：管理界面是中文，支付方便


配置：2核2G 就够用，每月 $5-10。

## 完整部署流程

### 第1步：买服务器

**配置选择：**
- 配置：2核2G 够用
- 系统：Ubuntu 22.04
- 位置：新加坡/香港/日本（国内访问快）

**拿到服务器后，记下 IP 地址和 root 密码。**

---

### 第2步：放行防火墙/安全组

**这一步很重要，容易忘！**

**什么是安全组/防火墙？**

服务器的保护机制，默认拦截所有外部访问。你要手动开放端口，才能让别人访问你的网站。

**怎么放行？**

**阿里云/腾讯云：**
1. 控制台 → 找到你的服务器
2. 安全组 → 配置规则
3. 添加规则：
   - 端口：80（HTTP）
   - 端口：443（HTTPS）
4. 来源：0.0.0.0/0（允许所有人访问）

**不放行的话，网站部署好了也访问不了。**

⚠️ **数据库端口(PostgreSQL 5432、MySQL 3306、Redis 6379)不要放行。** 本地要连数据库时用 vibe-launch 的隧道(见第 6 步)，不用开公网端口。

---

### 第3步：装 vibe-launch，接到你的 AI 工具上

这一步做完，后面部署、配域名、配 HTTPS 基本都是跟 AI 说一句话。

**1. 在你自己的电脑上装**（需要 Node.js）：

```bash
npm install -g vibe-launch
```

**2. 接到 Claude Code / Codex 上**，把这段加进 MCP 配置：

```json
{
  "mcpServers": {
    "vibe-launch": { "command": "npx", "args": ["-y", "vibe-launch", "mcp"] }
  }
}
```

不知道配置文件在哪，就把这段发给 AI，让它帮你加。

**3. 接入服务器、授权 GitHub**，整个流程里只有这两条要你自己敲：

```bash
vibe-launch server add prod --host 你的服务器IP --user root --password "你的密码"
vibe-launch auth
```

第二条会打开浏览器，点一下授权，之后 AI 部署时才能让服务器拉你 GitHub 上的代码。

自己敲，是为了不把服务器密码和 GitHub 授权发到对话里。它会配好 SSH 密钥，之后连服务器不用再输密码，AI 也是用这把钥匙去操作。

**SSH 是什么？** 就是远程连接到服务器。以前要自己生成密钥、配置免密登录，这一步 vibe-launch 帮你做了。

**4. 让 AI 把服务器准备好：**

```
看看 prod 这台服务器的网络情况，没装 Docker 的话帮我装上
```

它会先体检：Docker Hub、GitHub 这些连不连得上、连不上是什么原因，国内服务器经常卡在这里。然后装 Docker，装之前会先问你。国内服务器连不上 Docker 官方源，它会自动改用阿里云的源。

---

### 第4步：买域名

**推荐：** Namecheap / GoDaddy / 阿里云

买哪里的都行，海外服务器不限制域名来源。

**便宜的域名：**
- `.com`: $10-15/年
- `.xyz`: $1-2/年（第一年）
- `.top`: $3-5/年

---

### 第5步：域名托管到 Cloudflare

**为什么托管？**

域名商自带的 DNS 功能弱，Cloudflare 免费提供 HTTPS + CDN。

**什么是名称服务器？**

简单理解：**名称服务器就是告诉全世界"你的域名在哪里管理"**。

改成 Cloudflare 的名称服务器，就是把域名管理权交给 Cloudflare。

**步骤：**

1. 注册 Cloudflare 账号（cloudflare.com）
2. 添加站点，输入你的域名
3. 选择免费计划
4. Cloudflare 给你2个名称服务器（类似 `ns1.cloudflare.com`）
5. 去域名商后台，找到"名称服务器"或"DNS 设置"，改成 Cloudflare 给的
6. 等几分钟到几小时生效

Cloudflare 会发邮件通知"已激活"。

---

### 第6步：用 vibe-launch 部署项目

在 Claude Code / Codex 里直接说：

```
把我 GitHub 上的 你的用户名/仓库名 部署到 prod 服务器，起名 myapp
```

AI 会用 vibe-launch 一步步做完：
1. 让服务器能拉你的代码：装 git、生成只读的部署密钥、加到你的 GitHub 仓库
2. 看你的项目是什么类型（Vue/Next/Python/Node/静态页…），定好部署命令、端口和健康检查
3. 登记项目、部署
4. 查健康检查，确认项目真的跑起来了

**出问题不用你去翻日志。** 健康检查没过，它会自己读容器日志、看服务器的内存和磁盘，找到原因改完再部署一次。你要做的是看它最后给的结果。

先用 IP 加端口访问一下，比如 `http://你的服务器IP:8080`，确认能打开，再去配域名。

**以后改了代码**，推到 GitHub 后说一句"部署 myapp"就行。

**代码没放 GitHub 也可以**，说"把这个文件夹部署到 prod"，它会直接把本地代码传上去。

**想自己敲命令？** 上面每一步都有对应的命令，见 vibe-launch 的 README。

**其他常用**

- **想看界面:** `vibe-launch ui`，浏览器里看部署状态、回滚、看日志
- **本地要连服务器上的数据库:** `vibe-launch tunnel prod --service pg`，之后数据库工具连 `localhost:5432`，服务器的数据库端口不用对外开放

---

### 第7步：Cloudflare 添加 DNS 记录

让域名指向你的服务器。

**Cloudflare 控制台 → DNS → 添加记录：**

- 类型：A
- 名称：@ （代表根域名）
- IPv4 地址：你的服务器 IP
- 代理状态：已代理（橙色云朵）

如果有后端，再加一条：
- 名称：api
- 指向同一个 IP

等几分钟 DNS 生效。

---

### 第8步：配置 HTTPS

**两段都要加密:** 浏览器到 Cloudflare 这段，Cloudflare 自动提供免费证书；Cloudflare 到你服务器这段，用 Cloudflare 免费发的"源服务器证书"。我自己的服务器一直用的就是它，有效期默认 15 年，装一次基本不用管。

1. Cloudflare 控制台 → SSL/TLS → 源服务器 → 创建证书，默认选项就行。把"源证书"和"私钥"分别存成 `origin.pem` 和 `origin.key`(私钥只显示这一次，关掉页面就看不到了)
2. 跟 AI 说：

```
证书在 下载/origin.pem 和 下载/origin.key，存到 prod 上，然后把 app.example.com 接到 myapp，开 HTTPS
```

它会把证书传到服务器，再把域名接到项目上。不用把私钥内容贴给 AI，告诉它文件在哪就行，vibe-launch 直接把文件传上去，私钥不会出现在对话里。

**什么是反向代理？** 简单说：项目跑在服务器内部(比如 8080 端口)，反向代理把别人访问 `app.example.com` 的请求转给它。"把域名接到项目上"就是配反向代理。

**不懂端口？** 可以理解为：服务器内部有很多"门牌号"，8080 就是其中一个。

这台服务器第一次配域名时，它会先把反向代理准备好：服务器装过 1Panel，就直接写进 1Panel 里，不跟它抢；没装过，它装一个 Caddy，装之前会问你。每次改配置前都会先校验，写错了自动退回，不影响服务器上已有的网站。

3. Cloudflare 控制台 → SSL/TLS → 选择"完全（严格）"

你的网站就是 HTTPS 了。

> 域名没开 Cloudflare 代理(灰色云朵)的话，可以不配源站证书，跟 AI 说"不用源站证书"，Caddy 会自动申请免费证书。开了橙色云朵就用源站证书，自动申请在这种情况下可能失败。

访问 `https://example.com`，看到小锁图标就成功了。

## 小白容易搞错什么？

### 以为 localhost 别人也能访问

本地 `localhost:3000` 能打开，就以为别人也能访问。

**不行。** localhost 只有你自己能访问，部署后要用域名或 IP。

### 域名解析没配置

部署好了，访问域名打不开。

**原因:** 
- 忘了在 Cloudflare 添加 DNS 记录
- DNS 还没生效（要等几分钟）
- **或者服务器防火墙没放行端口 80/443**

**排查：**
1. 用 `ping example.com` 检查是否指向你的服务器 IP
2. 检查 Cloudflare DNS 记录是否添加
3. **检查服务器安全组是否放行了 80 和 443 端口**

### HTTPS 打不开

`http://example.com` 能打开，`https://example.com` 打不开。

**原因:** Cloudflare SSL 模式没设置。改成"完全"。

### 数据库端口开了公网

为了本地连数据库方便，把 5432、3306 这些端口对外放行了。

**问题:** 数据库直接暴露在公网，被扫到就可能被暴力破解。

**做法:** 端口关掉，要连的时候用 `vibe-launch tunnel`。`vibe-launch ui` 里的"端口暴露检测"可以帮你查哪些数据库端口还开着。

**背景知识最重要**

localhost、IP、域名、HTTP/HTTPS 的关系一定要搞清楚。
